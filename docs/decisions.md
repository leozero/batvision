# batvision — Decision log

Decisions made during the scoping session of 2026-11-11. Each one lists what was chosen, the options set aside, and why.

| #   | Decision                             | Choice                                                                                                                                                | Set aside                                                               | Why                                                                                       |
| --- | ------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------- | ----------------------------------------------------------------------------------------- |
| D1  | Audience                             | Personal and family first, then open source and Play Store                                                                                            | Commercial                                                              | Start from real use, publish afterwards                                                   |
| D2  | Relation to Jellyfin                 | **Full replacement, rewritten from scratch** (movies and series)                                                                                      | Fork, C# plugin, clients only on the Jellyfin API, or a Streamyfin fork | Full control over features; existing apps don't fit                                       |
| D3  | Server language                      | Rust (axum, SQLite)                                                                                                                                   | TypeScript, C#                                                          | Performance, a single binary, a strict compiler that guards AI-generated code             |
| D4  | Client language                      | TypeScript                                                                                                                                            | Native Kotlin                                                           | Code shared between web, desktop and mobile, generated API client                         |
| D5  | Desktop                              | Electron                                                                                                                                              | Tauri                                                                   | Chromium gives the same video playback everywhere and reuses the web code                 |
| D6  | Mobile and TV                        | Expo (React Native), react-native-tvos                                                                                                                | Kotlin, Capacitor                                                       | Shared TypeScript, native ExoPlayer, background work                                      |
| D7  | Downloads on the web                 | No: the web is for playback and control                                                                                                               | Browser storage, via a PWA                                              | Browser storage is fragile and can be evicted                                             |
| D8  | Where the rules live                 | The server computes an expected set per user × device; the client applies it                                                                          | Rules in each client                                                    | Deletion logic in a single, tested place                                                  |
| D9  | Watchlist                            | Movies only, per user, on the server. A watched movie leaves it                                                                                       | Mixed movies and series                                                 | Simplicity                                                                                |
| D10 | Series                               | Explicit request from the series page: `rolling(X)` (refilled over time) or `season(n)` (downloaded once)                                             | Automatically following series in progress                              | Nothing downloads without a user action                                                   |
| D11 | Deletion                             | Watched item deleted after 24 h. Per-device quota: watched first, then oldest                                                                         | —                                                                       | —                                                                                         |
| D12 | Mobile data                          | Off by default. Once on: monthly cap, lighter versions only                                                                                           | —                                                                       | —                                                                                         |
| D13 | Encoding                             | **Only when a device asks** (revised in milestone 3), in a queue, 1 at a time by default                                                              | Pre-encoding the library; encoding ahead of time from expected sets     | Too heavy for a home server                                                               |
| D14 | Profiles                             | `max` (video copied, AAC audio, MP4), `mobile` (720p, ~1.5 Mb/s), `saver` (480p, ~700 kb/s). AV1 if the device decodes it in hardware, otherwise HEVC | `original` (file as is)                                                 | MKV/AC3/DTS don't play in Chromium-based offline players; `max` keeps the video untouched |
| D15 | Offline sync                         | Uploaded as soon as the connection is back. Most recent watch date wins                                                                               | —                                                                       | Required for automatic deletion and "Next up"                                             |
| D16 | How a device learns it has downloads | It checks on its own: on open, when the network is back, every 15 min to 1 h                                                                          | Firebase push notifications                                             | No Google dependency; F-Droid publication possible                                        |
| D17 | Authentication                       | No public sign-up, password + 2FA (mandatory for admins), one token per device, quick connect for TV                                                  | Open sign-up                                                            | Server exposed to the internet                                                            |
| D18 | Exposure                             | Dokploy, with its Traefik for the domain and HTTPS                                                                                                    | Caddy in the docker-compose                                             | Dokploy is already in place                                                               |
| D19 | Direct play vs transcoding           | Each client declares what it can play; the server decides (direct, then remux, then audio only, then full transcode)                                  | —                                                                       | Jellyfin's model, simplified                                                              |
| D20 | Audio and subtitle tracks            | Per-user preferences. A change made on an episode applies to the whole series, matching the track by language and kind                                | Per-episode choice                                                      | Explicit request                                                                          |
| D21 | File recognition                     | Jellyfin/Plex naming convention, plus "Identify manually"                                                                                             | Automatic detection of unsorted files                                   | Folders are already organized that way                                                    |
| D22 | Migration from Jellyfin              | Not for now. Export/import will come later                                                                                                            | One-off import script                                                   | Out of scope for v1                                                                       |
| D23 | Android storage                      | App private space or SD card, chosen per device                                                                                                       | —                                                                       | —                                                                                         |
| D24 | Tests                                | Unit and e2e tests mandatory (Playwright, then Maestro)                                                                                               | —                                                                       | AI-written code                                                                           |
| D25 | Licenses                             | AGPL-3.0 for the server, GPL-3.0 for the clients                                                                                                      | MIT                                                                     | Prevents closed forks, compatible with the Play Store                                     |
| D26 | Milestone order                      | Server, then web, then download engine, then desktop, then Android, then TV                                                                           | Android before desktop                                                  | Desktop validates the download engine at lower cost                                       |
| D27 | Creating the first admin             | Single-use token printed in the logs on first start, entered along with the account                                                                   | Setup wizard open to anyone on first launch                             | Exposed server: nobody else can claim the admin account first                             |
| D28 | Images (posters, stills)             | Served without authentication, but only those referenced by the library, with a disk cache                                                            | Authenticated images                                                    | Usable in `<img>` tags. TMDB images are public anyway                                     |
| D29 | Detecting new files                  | Periodic full scan (every 15 min by default), plus on-demand scans                                                                                    | Filesystem watching                                                     | Reliable on network mounts too, where watching doesn't work                               |
| D30 | Disappeared files                    | The item is hidden, not deleted. It comes back with the same id if the file returns                                                                   | Immediate deletion                                                      | Watch history and watchlist stay attached                                                 |
| D31 | Stored tokens                        | Only a SHA-256 hash of tokens (devices, invitations, recovery codes) is stored                                                                        | Plain-text tokens                                                       | A database leak grants no access                                                          |
| D32 | Web session                          | HttpOnly, `SameSite=Strict` cookie; other clients use a bearer token                                                                                  | Token in `localStorage`                                                 | Exposed server: an injected script can't steal the session                                |
| D33 | Media URLs                           | HMAC-signed, valid 12 h; an HLS session id (256 bits) is the credential for its segments                                                              | Bearer header on media                                                  | `<video>` and `<track>` can't send headers                                                |
| D34 | Transcoding                          | One ffmpeg process per playing device, HLS fMP4 (H.264 + AAC, NVENC when available); seeking outside what's produced restarts the session there       | Pre-computed VOD playlist with on-demand segments                       | Much simpler; the restart costs a few seconds                                             |
| D35 | Subtitles on the web                 | Converted to WebVTT (cached), shifted to the stream start, drawn by the player itself; image subtitles burned in                                      | Browser's native cue rendering                                          | Consistent look, stays above the controls                                                 |
| D36 | Resume and watched                   | Resume from 60 s; watched at 90 %; a stopped episode stays "next up"                                                                                  | Fixed thresholds per client                                             | One rule for every client, on the server                                                  |
| D37 | Episode order                        | Specials (season 0) after the regular seasons, never in the middle of "next up"                                                                       | Air-date order                                                          | Specials rarely belong to the main story                                                  |
| D38 | Visual design                        | Dark theme, amber accent, top navigation, rows of cards, vertical episode list, Netflix-style track panel; motion on pages, cards, hero, dialogs      | Sidebar navigation (Jellyfin)                                           | References from streaming services on Mobbin                                              |
| D39 | Setup token                          | Random and printed in the logs, or fixed with `BATVISION_SETUP_TOKEN`                                                                                 | —                                                                       | Lets automated tests (and admins who prefer it) choose it                                 |
| D40 | Download audio                       | One audio track per download, chosen when requesting (default: preferred audio language); all text subtitles as WebVTT                                | Every audio track                                                       | Smaller files, the choice is made once                                                    |
| D41 | Encoded cache                        | 50 GB budget; a variant is deleted once every requesting device confirmed its download                                                                | Keep variants for reuse                                                 | The server is short on disk; devices keep the file                                        |
| D42 | Automatic downloads                  | Off by default on every device, set in the Downloads page; only the watchlist depends on it                                                           | On by default on Android                                                | Nothing downloads without an explicit choice                                              |
| D43 | What a device holds                  | Recorded at confirmation, pruned when the item leaves the expected set                                                                                | Derived from variants                                                   | Variants are deleted after download                                                       |
| D44 | Offline progress                     | Uploaded in batch; a record older than the server's last watch is ignored                                                                             | Last write wins                                                         | Watching elsewhere in the meantime must not be undone                                     |
| D45 | Desktop interface source             | The app ships its own build of the web interface; the server address is entered on first launch                                                       | Loading the server's web page                                           | Works offline                                                                             |
| D46 | Desktop credentials                  | Device bearer token, encrypted with the OS keychain (Electron `safeStorage`)                                                                          | Session cookie                                                          | Survives restarts, never stored in plain text                                             |
| D47 | One interface for web and desktop    | Same React app; download features appear only when the desktop bridge is present                                                                      | A separate desktop UI                                                   | One code base to maintain                                                                 |
| D48 | Desktop storage                      | `Videos/Batvision` by default, changeable; 100 GB quota by default (watched first, then oldest)                                                       | App data folder                                                         | Visible to the user, easy to move to another disk                                         |
| D49 | Offline mode                         | When the server is unreachable, an offline library shows only downloaded items, played by the same player                                             | A separate offline player                                               | Same experience, tracks and resume included                                               |
| D50 | Offline metadata                     | Only downloaded items' metadata and images, in a JSON file                                                                                            | SQLite (native module)                                                  | No native builds per platform                                                             |
| D51 | Desktop background work              | Closing the window keeps the app in the tray; sync on open, when the network returns and every 30 min; launch at login off by default                 | Quitting on close                                                       | Downloads and deletions keep running                                                      |
| D52 | Desktop network rules                | No network restriction, one download at a time, pause/resume, resume after interruption (HTTP Range)                                                  | Wi-Fi only                                                              | A computer has no mobile data                                                             |
| D53 | Desktop device profile               | `max` by default; AV1/HEVC hardware decoding detected automatically                                                                                   | Asking the user                                                         | Nothing to configure                                                                      |
| D54 | Accounts per desktop install         | One signed-in account per install; sharing files between accounts is left to Android                                                                  | Several accounts                                                        | Rare on a computer                                                                        |
| D55 | Desktop builds                       | macOS (arm64, x64), Windows, Linux AppImage, built in CI, unsigned until milestone 7; no auto-update yet                                              | Signed builds now                                                       | Signing costs money and only matters for the release                                      |
| D56 | Desktop tooling and tests            | electron-vite + electron-builder, latest Electron; Playwright Electron e2e against a real server                                                      | Electron Forge                                                          | Shares Vite with the web app                                                              |
| D57 | GPU video pipeline                   | When the startup probe shows it works, decoding (NVDEC), scaling and HDR tone mapping (`tonemap_cuda`, BT.2390, Dolby Vision aware) run on the GPU for streaming and download encodes; formats NVDEC doesn't take are decoded on the CPU and uploaded; burned-in subtitles are overlaid on the CPU after scaling; a failed GPU encode is retried on the CPU; CUDA kernels cached in `/cache/cuda` | CPU decode and float tone mapping at full resolution | Measured on a 4K Dolby Vision film to 480p AV1: 0.33x real time on the CPU, 19x on the GPU |
