# batvision — Decision log

Decisions made during the scoping session of 2026-11-11. Each one lists what was chosen, the options set aside, and why.

| #   | Decision                             | Choice                                                                                                                      | Set aside                                                               | Why                                                                           |
| --- | ------------------------------------ | --------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------- | ----------------------------------------------------------------------------- |
| D1  | Audience                             | Personal and family first, then open source and Play Store                                                                  | Commercial                                                              | Start from real use, publish afterwards                                       |
| D2  | Relation to Jellyfin                 | **Full replacement, rewritten from scratch** (movies and series)                                                            | Fork, C# plugin, clients only on the Jellyfin API, or a Streamyfin fork | Full control over features; existing apps don't fit                           |
| D3  | Server language                      | Rust (axum, SQLite)                                                                                                         | TypeScript, C#                                                          | Performance, a single binary, a strict compiler that guards AI-generated code |
| D4  | Client language                      | TypeScript                                                                                                                  | Native Kotlin                                                           | Code shared between web, desktop and mobile, generated API client             |
| D5  | Desktop                              | Electron                                                                                                                    | Tauri                                                                   | Chromium gives the same video playback everywhere and reuses the web code     |
| D6  | Mobile and TV                        | Expo (React Native), react-native-tvos                                                                                      | Kotlin, Capacitor                                                       | Shared TypeScript, native ExoPlayer, background work                          |
| D7  | Downloads on the web                 | No: the web is for playback and control                                                                                     | Browser storage, via a PWA                                              | Browser storage is fragile and can be evicted                                 |
| D8  | Where the rules live                 | The server computes an expected set per user × device; the client applies it                                                | Rules in each client                                                    | Deletion logic in a single, tested place                                      |
| D9  | Watchlist                            | Movies only, per user, on the server. A watched movie leaves it                                                             | Mixed movies and series                                                 | Simplicity                                                                    |
| D10 | Series                               | Explicit request from the series page: `rolling(X)` (refilled over time) or `season(n)` (downloaded once)                   | Automatically following series in progress                              | Nothing downloads without a user action                                       |
| D11 | Deletion                             | Watched item deleted after 24 h. Per-device quota: watched first, then oldest                                               | —                                                                       | —                                                                             |
| D12 | Mobile data                          | Off by default. Once on: monthly cap, lighter versions only                                                                 | —                                                                       | —                                                                             |
| D13 | Encoding                             | On demand, in a queue, started ahead of time from expected sets. Cache with a size budget                                   | Pre-encoding the whole library                                          | Saves disk and GPU                                                            |
| D14 | Profiles                             | `original`, `mobile` (720p, ~1.5 Mb/s), `saver` (480p, ~700 kb/s). AV1 if the device decodes it in hardware, otherwise HEVC | Fixed codec                                                             | Reference server GPU (RTX 5060) encodes both AV1 and HEVC                     |
| D15 | Offline sync                         | Uploaded as soon as the connection is back. Most recent watch date wins                                                     | —                                                                       | Required for automatic deletion and "Next up"                                 |
| D16 | How a device learns it has downloads | It checks on its own: on open, when the network is back, every 15 min to 1 h                                                | Firebase push notifications                                             | No Google dependency; F-Droid publication possible                            |
| D17 | Authentication                       | No public sign-up, password + 2FA (mandatory for admins), one token per device, quick connect for TV                        | Open sign-up                                                            | Server exposed to the internet                                                |
| D18 | Exposure                             | Dokploy, with its Traefik for the domain and HTTPS                                                                          | Caddy in the docker-compose                                             | Dokploy is already in place                                                   |
| D19 | Direct play vs transcoding           | Each client declares what it can play; the server decides (direct, then remux, then audio only, then full transcode)        | —                                                                       | Jellyfin's model, simplified                                                  |
| D20 | Audio and subtitle tracks            | Per-user preferences. A change made on an episode applies to the whole series, matching the track by language and kind      | Per-episode choice                                                      | Explicit request                                                              |
| D21 | File recognition                     | Jellyfin/Plex naming convention, plus "Identify manually"                                                                   | Automatic detection of unsorted files                                   | Folders are already organized that way                                        |
| D22 | Migration from Jellyfin              | Not for now. Export/import will come later                                                                                  | One-off import script                                                   | Out of scope for v1                                                           |
| D23 | Android storage                      | App private space or SD card, chosen per device                                                                             | —                                                                       | —                                                                             |
| D24 | Tests                                | Unit and e2e tests mandatory (Playwright, then Maestro)                                                                     | —                                                                       | AI-written code                                                               |
| D25 | Licenses                             | AGPL-3.0 for the server, GPL-3.0 for the clients                                                                            | MIT                                                                     | Prevents closed forks, compatible with the Play Store                         |
| D26 | Milestone order                      | Server, then web, then download engine, then desktop, then Android, then TV                                                 | Android before desktop                                                  | Desktop validates the download engine at lower cost                           |
| D27 | Creating the first admin             | Single-use token printed in the logs on first start, entered along with the account                                         | Setup wizard open to anyone on first launch                             | Exposed server: nobody else can claim the admin account first                 |
| D28 | Images (posters, stills)             | Served without authentication, but only those referenced by the library, with a disk cache                                  | Authenticated images                                                    | Usable in `<img>` tags. TMDB images are public anyway                         |
| D29 | Detecting new files                  | Periodic full scan (every 15 min by default), plus on-demand scans                                                          | Filesystem watching                                                     | Reliable on network mounts too, where watching doesn't work                   |
| D30 | Disappeared files                    | The item is hidden, not deleted. It comes back with the same id if the file returns                                         | Immediate deletion                                                      | Watch history and watchlist stay attached                                     |
| D31 | Stored tokens                        | Only a SHA-256 hash of tokens (devices, invitations, recovery codes) is stored                                              | Plain-text tokens                                                       | A database leak grants no access                                              |
